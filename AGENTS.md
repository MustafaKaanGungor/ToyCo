# ToyCo — Agent Guide

## Project
Unity 2D URP game (Unity **6000.0.59f2**). Created from `com.unity.template.universal-2d@5.1.0`.

## Scenes
- `Assets/Scenes/GameScene.unity` — main play scene (Camera + Light only).
- `AbdulScene.unity` / `MustiScene.unity` — developer sandboxes; not in build settings.

## Key packages
- **DOTween** (Demigiant) — `DOTWEEN` scripting define set; namespace `DG.Tweening`.
- **Input System** 1.14.2 — action asset at `Assets/InputSystem_Actions.inputactions`.
- **URP** 17.0.4, **Cinemachine** 3.1.6.
- **TextMesh Pro** — available in `Assets/TextMesh Pro/`.
- **Unity Test Framework** 1.6.0 — no tests written yet.

## Scripts
All under `Assets/_Scripts/`, grouped by system folder (`InputSystem/`, `UnitSystem/`, `Player/`).

| File | Role |
|---|---|
| `GameEvents.cs` | Static event bus — `OnMoveInput`, `OnSelectionChanged`, `OnCharacterConfirmed`, `InteractWithTribe` |
| `GameManager.cs` | Singleton MonoBehaviour (`GameManager.Instance`) |
| `InputSystem_Actions.cs` | **Auto-generated** from `.inputactions` — never edit by hand; regenerate via Input Action asset editor |
| `InputHandler.cs` | Wires Input System `Player.Move` → `GameEvents.TriggerMoveInput` |
| `PlayeController.cs` | Moves player Rigidbody2D via `GameEvents.OnMoveInput`. **Note:** class name has a typo (missing `r`) |
| `CharacterSO.cs` | ScriptableObject for character data + 6 enums (`Boy`, `Gender`, `HairStyle`, `EyeStyle`, `MouthStyle`, `BodyStyle`) |
| `CharacterSelection.cs` | Manages character selection in world space — spawns prefabs, click-to-select, confirm flow |
| `CharacterDisplay.cs` | Per-character world-space display — sprite, DOTween bob/select/deselct, `OnMouseDown` for clicks |
| `ConfirmClickable.cs` | World-space UI Button — DOTween appear/punch + proxies click to `CharacterSelection.ConfirmSelection` |
| `MapUnit.cs` | Abstract patrol AI — bounds, movement, wait timers, `OnTriggerEnter2D` → `Interact(MapUnit)` |
| `Tribe.cs` | Concrete `MapUnit` — random wander, tribe-type-based interaction |
| `Sheep.cs` | Concrete `MapUnit` — flees from player when interacted |
| `IMapInteractable.cs` | Interface: `OnInteracted(MapUnit)` / `OnWithdraw(MapUnit)` |
| `Player.cs` | Implements `IMapInteractable` — dispatches tribe interactions to `GameEvents.InteractWithTribe` |

## Event flow

```
InputSystem_Actions (.inputactions)
  → InputHandler (subscribes to Player.Move performed/canceled)
    → GameEvents.TriggerMoveInput(Vector2)
      → PlayeController.OnMove → FixedUpdate moves Rigidbody2D

CharacterDisplay.OnMouseDown → CharacterSelection.OnCharacterClicked
  → GameEvents.TriggerSelectionChanged(CharacterSO)
  → ConfirmClickable (Button.onClick) → CharacterSelection.ConfirmSelection
    → GameEvents.TriggerCharacterConfirmed(CharacterSO)
```

## Build / Lint / Test

- **No CI/build scripts** — standard Unity Editor workflow. Open `.sln` in VS Code with the `visualstudiotoolsforunity.vstuc` extension.
- **`.csproj` / `.sln`** files are gitignored (auto-generated by Unity).
- **Linting:** None configured. Unity's built-in warnings/errors are the only guard.
- **Tests:** Unity Test Framework 1.6.0 available. To run tests:
  - **Editor:** Window → General → Test Runner → Run All
  - **CLI (single test):** Not configured. Unity CLI test running requires `Unity.exe -runTests -testPlatform PlayMode -testResults result.xml`. No PlayMode or EditMode test assemblies exist yet — create one via Test Runner window → Create PlayMode/EditMode Test Assembly Folder.
- **Regenerate Input bindings:** Open `Assets/InputSystem_Actions.inputactions` in editor → Save.

## Code style

### Naming
| Kind | Convention | Example |
|---|---|---|
| Classes | PascalCase | `CharacterSelection`, `MapUnit` |
| Interfaces | PascalCase, `I` prefix | `IMapInteractable` |
| Enums | PascalCase | `Boy`, `HairStyle` |
| Enum members | PascalCase | `Boy.Boy1`, `Gender.Male` |
| Public fields | camelCase | `characterName`, `characterPrefab` |
| Private fields | `_camelCase` (underscore prefix) | `_selectedIndex`, `_moveSpeed` |
| Properties | PascalCase | `CharacterData`, `TribeType` |
| Methods | PascalCase, `On`-prefix for Unity/events | `Select()`, `OnInteracted()`, `OnMouseDown()` |
| Parameters / locals | camelCase | `display`, `randomIndex` |
| Static events | PascalCase, `On`-prefix | `OnSelectionChanged`, `OnCharacterConfirmed` |
| Trigger methods | `Trigger`-prefix | `TriggerMoveInput()` |

### Access modifiers
**Always explicit.** Never rely on C# defaults — every field/method has `public`, `private`, `protected`, or `protected override` stated. No implicit `private` anywhere.

### Serialization
Two patterns exist (both acceptable, but prefer `[SerializeField] private`):
- **Prefer:** `[SerializeField] private float \_speed = 5f;` — serialized private with inline default
- **Legacy OK:** `public List<CharacterSO> characterList;` — public field (used in `CharacterSelection`, `CharacterSO`)
- Use `[Header("Label")]` to group related serialized fields.

### Brace style
- **Class / method / property declarations:** Allman (brace on next line)
- **Control flow (`if`, `else`, `foreach`, `while`):** K&R (brace on same line)
- Example:
  ```csharp
  private void Start()
  {
      if (condition)
      {
          DoWork();
      }
  }
  ```

### Spacing
- One blank line between methods and between field blocks.
- No blank lines between related `[Header]` + `[SerializeField]` fields.
- Space after `if` / `foreach` / `while` keywords: `if (x)` not `if(x)`.
- No trailing whitespace on lines.

### Imports
- Order: `System.*` → `UnityEngine.*` → `UnityEngine.UI` → third-party (`DG.Tweening`)
- No blank lines between import groups.
- Only import what you use. Remove unused imports.

### `var` usage
**Avoid `var`** except for:
- `out var` with `TryGetComponent`: `other.TryGetComponent(out var player)`
- `foreach` loop variables where the type is obvious: `foreach (var position in positions)`
- Variables initialized from `GetComponent<T>()` or `Instantiate()` where the type is unambiguous.
- Always use explicit types for primitives and simple assignments: `int index = ...`, `float x = ...`.

### Namespaces
**None.** All scripts are in the global namespace. Do not add namespaces to new scripts without discussion.

### Comments
**Minimal.** The codebase has almost no comments. Inline comments are in Turkish when present. XML doc comments (`///`) are only in the auto-generated `InputSystem_Actions.cs`. Follow this pattern: write self-documenting code; comment only to explain _why_, never _what_.

### Event bus
Use `GameEvents` as the central event bus. Pattern for new events:
```csharp
public static event Action<MyType> OnMyEvent;
public static void TriggerMyEvent(MyType arg) => OnMyEvent?.Invoke(arg);
```
Use proper `event` keyword (not raw delegate fields). Subscribers use `+=` in `OnEnable` / `-=` in `OnDisable`.

### DOTween
- Project uses `DOTWEEN` scripting define; import via `using DG.Tweening;`.
- Kill tweens before replacing: `\_tween?.Kill();`
- For UI animations, use `DG.Tweening` (not `DOTweenModuleUI`) on RectTransforms via `DOScale`, `DOPunchScale`, etc.

### General
- **`[RequireComponent]`** on scripts that depend on specific components (e.g., `SpriteRenderer`, `Button`).
- **Don't duplicate** sprite-flipping via `localScale` — it exists in three files; if you touch that logic, consider centralizing.
- **Don't edit `InputSystem_Actions.cs`** — regenerate from the `.inputactions` asset instead.
- **Prefab directory** (`Assets/Prefabs/`) is empty — place new prefabs here.
